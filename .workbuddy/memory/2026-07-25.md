## 项目：Web-to-AI Context Chat（Chrome MV3 扩展）
目录 `/Users/cenwenchu/Desktop/Demo/agentPlugin`。把网页表格/截图/多屏作为上下文注入 OpenAI 兼容 Chat 浮层，并支持对页面表格绑定"技能"做整表或按列 AI 分析。

### 分层架构
1. **background.js**（Service Worker）：右键菜单、toolbar 点击、`chrome.runtime.onMessage` 路由、AI 请求代理（非流式 + SSE Port）、技能写入串行队列 `enqueueSkillMutation`、跨 tab/frame 采集协调、jtv1 业务页签、多屏截图。
2. **content scripts**（`src/content/*`，`all_frames:true`）：`loader.js` 动态 import `main.js`；`main.js` 注册消息监听、storage 监听、初始化。
3. **纯逻辑模型**（无 DOM/chrome，可 Node 单测）：`context-model`、`token-budget`、`skill-*-model`、`derived-column-*`、`spreadsheet-file`、`skill-collection-model`、`sse.js`。
4. **DOM/UI 模块**：`overlay.js`（Shadow DOM 浮层，最大）、`table.js`、`skills.js`、`dialog`、`toast`、`highlight`。
5. **options**（多模型配置页）。

### 关键子系统
- **表格选择**：`table.js` + `table-row-dom`/`table-header-resolver`/`table-pagination-dom`/`table-adapters`。`tableKey` = frame 运行实例 + 组件根 `WeakMap` 编号（同 URL 多 iframe 隔离）。虚拟滚动回收 DOM 但保留文本快照；check/bar = z-index 999。
- **上下文**：`context.js` + `context-model`（按 `headerRef`→`tableId` 分组）+ `token-budget`（保护预算，中文≈1字1token）+ `context-ref`。不持久化。
- **技能**：`skills.js` facade + `skill-source-dom`（定位/校验/读当前渲染行）+ `skill-collector`（分页/虚拟滚动采集）+ `skill-storage-model`（background 串行 mutation + `revision` 冲突检测）+ `skill-request-model`（请求装配 + 多数据源平均预算）。整表分析 1–5 数据源；按列分析 1 数据源、原生插列。
- **按列分析**：`derived-column-*`。runtime cache（内存 + `storage.session`，TTL 2h，`analysisFingerprint:rowFingerprint` 键）；频控 `pageGuardKey=pageKey+modelId`；批量接口 `triggerDerivedColumnRuntime`。
- **截图/多模态**：`chrome.tabs.captureVisibleTab` JPEG82；region 用 Canvas 裁剪；多屏最多 5 屏。
- **业务页签 jtv1/聚水潭 epaas**：`business-tab-dom.js`，顶层 URL 不随业务切换，用 `businessTabTitle` 归属；`?n=` 直达 URL。
- **通信**：`overlay → messaging(Port) → background(fetch SSE) → messaging → scheduleRender`；跨 frame 经 background 转发。

### 架构模式 / 坑
- **循环依赖规避**：回调注入（`context.js` 的 `initContextDependencies`、`skill-workspace-controller` 的 `initSkillWorkspaceController({render})` 由 overlay 注入）；`refs` 共享可变注册表（state.js）。`module-boundaries.test.mjs` 固化边界。

### 调研：jtv1「按列分析」渲染 bug（17:11，仅讨论未改）
- 现象（用户反馈）：① 输出列落到第一列；② 底部行结果错位到上面几行；③ 原表字段/格式整体错位破碎。
- jtv1 真实结构（erpDemoFile/erptable.txt）：表头 `#_jt_row_head > #_jt_row_head_list > ._jt_cell_head`（含 `_jt_cell_head_index`、`._jt_cbx` 复选框列，需过滤）；表体 `#_jt_body > ._jt_row._jt_rh`，子单元为 `._jt_cell`（含 `._jt_cell_index`、`._jt_ch`）。`#_jt_body` overflow-y 撑开→**非虚拟滚动**，行节点稳定。
- 渲染器 jtv1 分支（`derived-column-renderer.js`）：
  - `ensureDerivedHeader`（187-222）：jtv1 给派生表头加 `._jt_cell_head` 类 → 表头 OK。
  - `ensureDerivedBodyCell`（224-255）：jtv1（rowEl 是 div）只建裸 `<div data-web2ai-derived-column>`，**未加 `._jt_cell`** → 与兄弟 `._jt_cell` 不同构。
  - `resolveInsertChild`（120-136）：jtv1 走 `adapter.rowCells` 分支，`businessCells[insertIndex]`。
- `insertIndex = resolveDerivedInsertIndex(selectedColumns)`（controller 643、509-515）= **所选列最小 index**；若 selectedColumns 为空→回退 0 → 落在第一列（现象①）。
- **校准（用户答复：①首次渲染就错位；②结论列应紧挨"所选列最左列"的前面）**：
  - ② 在**首次渲染**就发生 → 排除旧假设"行节点重建导致 rowEl 复用错位"。② 现判定与 ③ **同源**：body 派生单元是裸 `<div data-web2ai-derived-column>`（无 `._jt_cell`），作为 flex 兄弟项与 `._jt_cell` 不同构，撑破 `._jt_row` 行内布局 → 整行节奏错位，视觉上表现为"底行结果跑到上面几行"。
  - ① 用户明确要"紧贴所选最左列之前" → 即 `resolveDerivedInsertIndex=min(selectedColumns.index)` 的**期望行为**。故 ① 主因不是插入逻辑错，而是：**selectedColumns 解析为空→回退 insertIndex=0**（落到第一列）；或**（次因）** body 缺 `._jt_cell` 导致该列视觉未被 flex 正确排进对应槽位，看起来"全堆在第一列"。
  - 代码实证：`buildRuntimeRows`（201-259）`selectedColumns` 为空时 `selectedValues=[]`→所有行 `rowFingerprint=buildDerivedColumnRowFingerprint([])` **恒定相同**→`buildRuntimeUniqueRows` 把所有行合并成 1 个 uniqueRow→所有行显示**同一结论**（这是空选列的另一表象，不是"底→顶"）。
- **结论：③ 是 primary root cause，修 ③（body 派生单元补 `._jt_cell` 与兄弟同构）大概率同时消解 ①(视觉) 与 ②；① 的"空选列→0"需另修兜底（空选列时插入到末尾而非第一列）。**
- 修复方向（讨论稿 v2）：① **`ensureDerivedBodyCell` 对 jtv1 补 `._jt_cell`**（必要时 + `_jt_ch`、显式 width/flex），与 `ensureDerivedHeader` 的 `._jt_cell_head` 对称；② `resolveDerivedInsertIndex` 在 selectedColumns 为空时返回 `headers.length`（追加到末尾），有选列时维持 `min(index)`（=用户要的"最左列之前"）；③ 行稳定性：因首次渲染即错位，重建假设可暂不处理，优先验证 body 类修复是否连带解决 ②。
- 待办：本机无 jtv1 真实页+Chrome，未实跑 e2e；计划用 jsdom 加载 `erptable.txt` 真实 `_jt_` 结构做**无 Chrome 的 DOM 级验证**（确认插入位置 / 空选列 dedup / body 是否缺类），视觉错位需真实浏览器截图确认（扩展 `jtv1-table-recognition.mjs` 模式）。
